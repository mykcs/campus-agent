# Progress 与今日看板交互规范

> Owner：Design · 状态：active MVP

## 1. 用户旅程

```text
关注学院/主题 → 浏览公开通知 → 点标题到学校官网核对
                                      │
                             看见未核实日期线索
                                      ▼
                         用户明确核对截止日期并跟踪
                                      ▼
                  Progress 长条 + 个人状态 + 剩余天数
                                      │
                   今日看板（7天内/逾期/进行中）
                    ├─ 仍未开始 → 未开始
                    ├─ 已在准备 → 进行中
                    └─ 完成提交 → 已完成（留痕）
                                      │
              可选下载 .ics / 在 Google Calendar 创建日程
```

## 2. 页面层级

左侧主导航：我的动态 → 进度与今日任务 → 校园问答 → 数据来源。

Progress 页首屏只放「申请进度」标题、添加任务与导出日历操作、日期精度说明，以及适当轻量统计。核心是：今日看板、申请窗口长条、待核对日期线索，**不重复首页的学院概况与公告列表**。

## 3. 状态语言

- **还剩 N 天**：日期属于用户已确认的任务；按用户确认的截止时区日历日显示；旧任务保留 SGT 语义。不得暗示必须在这一时刻之前完成所有事项。
- **今天截止**：当日任务，原通知时间如仍未知，明确只按日期显示；若确认了时刻且已过去，显示已到截止时间。
- **已逾期 N 天**：不等于学校拒绝；用户仍可标记已经完成、保留历史或移除。
- **已完成**：用户自己选择，UI 和本地状态保留；不能因时间条达到100%自动完成。
- **待核实日期线索**：由抓取器自动识别的候选，单独展示「读原文」「核对并跟踪」，不进入今日看板。

## 4. 时间条应表达什么

一条卡片包含：官网标题、状态与剩余天数、从**公告日期**到**个人已确认截止日**的横向进度条、时间起点和截止日期。填充的百分比是**时间经过**，不能称作「完成百分比」。已完成状态与条的颜色分别表达，不相互推断。

同一公告可能有多轮报名、多种学位、不同材料截止，所以支持多个个人任务，不能因为 URL 相同而自动强行去重。

## 5. 外部日历交互

目前按钮明确写「导出我的日历 .ics」，下方强调**一次性**；Google 的操作写「加入 Google 日历」，它打开预填模板，由用户保存。不要使用「已订阅」「自动更新」「双向同步」等误导文案。

如未来推出订阅，单独告知共享链接可访问范围、撤销方法、刷新时延、Apple/Google 行为差异，以及任务信息何时上传服务器。

## 6. 移动端

- 390px iPhone 布局：无横向页面滚动；主导航可单独横向滑动；按钮适合触摸。
- 时间条横向撑满容器，标题先于操作控件；长日期可换行。
- 查看公告应直接打开官方链接，不通过 AI 解释取代原文。
- 刷新不会重置任务状态；清空站点数据的风险在 Dev 文档及帮助文案明示。

## 7. 有意不做

月视图、复杂会议邀请、跨设备任务同步、重复事件规则、在 Calendar 中打钩反向回传、无来源的自动申报日程、学校账号代登录。

日期线索按开始、截止、内部、推荐、邮戳、待核对类型分别呈现，保留适用范围和原文 URL。缺年份或不完整时刻不自动补全；明确时区与用户核对后才计入任务。
