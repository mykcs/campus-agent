# Markdown — 文档与证据格式

该目录存放**文档写作约定和模板**，不是用于复制代码、模型提示或收集用户隐私。开发者创建新的 Markdown 时优先使用 [TEMPLATE.md](TEMPLATE.md)，并放入有权威归属的目录：

- 产品想法、希望避免的失败 → `docs/wish/`
- 交互原则、视觉对比、原型 → `docs/design/`
- 实际 API/数据合同/技术决定 → `docs/dev/`
- Agent 操作边界与路由 → `docs/agents/`
- 对所有人有用的导航 → 根级 `README.md` / `docs/README.md`

**原则**：首次出现的概念用简体中文解释；可直接点的官方链接优先于不可追溯的摘要；完成、部分完成、尚未做分别写；日期必须带年份和必要时区；用户原始意图与 Agent 提案分清。不要把“用户希望实现”和“已经上线”写成同一句事实。

Markdown 信息宜短，长证据可以分专题文档。避免多处复制同一决定：用链接指向唯一 owner。不要记录 API Key、校园密码、浏览器 Cookie、学生私人资料或未经同意的日志。
