# Agent 不可变约束

**适用范围**：Campus Agent 网站和本地应用任务流程。更新日期：2026-11-19。

1. **事实分层**：`published_at` 是来源元数据，`date_candidates` 是未经确认的算法结果，`deadlineDate` 是学生阅读官方原文后自己确认并添加的个人任务日期。不可互相替代。
2. **不猜资格**：无学历/专业/年级/推荐人等证据时，不能声称「符合申请资格」。只能列出处置步骤和仍需确认的信息。
3. **任务是个人状态**：任务状态 `todo / doing / done` 不能被 AI 自动置为完成；完成时间由用户操作产生。日期过期也不会自动表示失败、拒绝或已经放弃申请。
4. **日期和时区**：源通知以官方原文为准；本项目个人日期显示按 SGT（UTC+8）计算日历日。若官方截止小时未知，导出时采用全天日程，并明确是个人占位而非精确提醒。
5. **来源可追踪**：所有可操作事项附可检查的官方 URL，UI 与数据区分 `ok / partial / degraded / error`。引用被撤回或抓取失败时不能悄悄声称无新通知。
6. **隐私、凭据与浏览器**：仅抓无需登录的公开网页。不索取学校密码，不共享用户 localStorage、API Key 或个人进度，不通过 URL 发布个人私有订阅数据。
7. **外部日历**：`.ics` 是标准的可交换日历格式，但当前仅一次性导出，Apple/Google 的完成状态不会写回本站。不得把文件下载描述为已创建自动订阅。
8. **模型可选**：没配置 BYOK 的用户仍能读取通知、维护进度、导出日历；定时采集不可依赖模型或 ChatGPT 在后台常驻。
9. **最小成本**：在 Hobby 与 GitHub 免费额度内优先工作；新增有成本的数据库、OAuth 商业服务、推送平台前先提供实证与选择。
10. **反例测试**：报名开始日不是截止日、年度不是日期、推荐截止日不等于学院内部截止日、同篇公告可以有多个申请途径。避免只按关键字识别出一个“最终截止”。
